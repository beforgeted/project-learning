# 项目记录模板与更新规则

按需要使用下面的模板；已有格式优先。对简单尝试可压缩为一段记录。需要支撑结论但缺失的字段应标明未知，不为无关字段制造占位内容。

## 标识与来源

沿用已有记录 ID。新建时可用项目内唯一的 `A-001`（方案）、`E-001`（实验）、`L-001`（经验）、`SOP-001`，从现有最大编号续编；需求、资源、问题和评价的标识与公共字段见 [platform-handoff.md](platform-handoff.md)。跨项目引用带项目名和链接。多人并发写入共享库时，优先使用平台生成的唯一 ID，避免各自从相同序号续编。

使用实际已知的发生日期；回补历史时把记录日期与发生日期分开，不知道发生日期就注明。来源分类用于明确证据性质，不用于自动抹去矛盾：

| 来源 | 怎样记录 | 能支持什么 |
|---|---|---|
| 可查看的执行产物、样本或评估结果 | 文件或页面链接、运行 ID、版本、具体表格或片段 | 产物实际覆盖的观察结果 |
| 用户报告 | 谁在何次可见讨论中说明了什么，产物是否查看 | 已报告事实；独立核验状态仍需注明 |
| 讨论决策 | 讨论定位、明确选项及可见理由 | 选择与约束，不能证明效果 |
| AI 或人的建议 | 建议来源、假设、验证办法 | 待验证方案，不能证明执行或有效 |

聊天没有可用链接时，用“当前讨论 + 可定位的主题或简短摘录”，不要虚构消息 ID。脚本、截图、配置导出、平台运行页、表格和抽检报告都是合法证据；能访问才声明已查看。

## 项目索引

```markdown
# 项目名称

- 项目边界与业务目标：
- 当前阶段：
- 关联需求、规则与资源目录：
- 输入与预期交付：
- 主要约束：成本、时效、数据范围等相关项
- 验收口径与来源：尚未确定时明确注明
- 记录范围与位置：哪些材料已纳入，哪些尚不可访问
- 最近更新：

## 当前结论与未决事项
简述当前选择、关键风险或待验证问题，链接到具体记录。

## 记录导航
仅链接实际存在的方案、实验、经验及 SOP。
```

索引保持简短。详细结果只有一份权威记录，其他位置用链接引用。

## 方案 / 决策记录

```markdown
### A-001 · 方案名称

- 日期与来源：
- 要解决的问题与约束：
- 对应需求 ID 与版本：
- 方案版本及方式：复用 / 组合 / 全新，允许按步骤混合
- 候选方案及取舍：
- 当前选择及理由：未决时注明未决
- 参考项目、方案和经验：采用点、条件差异、排除理由
- 跨项目复用审查：实际借用的主张、方法/配置/效果分类、必要条件、冲突处理、目标步骤及具体重验项；见 [cross-project-reuse.md](cross-project-reuse.md)
- 状态：提出 / 已选择 / 暂缓 / 放弃 / 已替代
- 待验证假设及成功标准：已有标准注明来源；新建议注明待确认
- 实施入口：提示词、平台配置、流程图或脚本等适用项
- 步骤与资源映射：每步资源 ID/版本、输入输出衔接、规则版本、缺失依赖
- 关联实验：
- 后续变化：日期、变化、原因及替代方案链接
```

执行状态放在实验记录。不要把“放弃”都解释成“实验失败”，有些是成本、期限或范围选择。

## 实验 / 实际尝试记录

```markdown
### E-001 · 尝试名称

- 日期、执行者（已知时）与来源：
- 关联方案 ID/版本、需求及验证问题：
- 上游实验与关系：复现 / 对照 / 改进 / 纠错 / 新批次验证等适用项
- 执行状态：计划 / 执行中 / 完成 / 失败 / 中止
- 输入范围：样本或批次标识、数量、选择方法、相关分层
- 实施方式与配置：模型、提示词、规则、Agent 链路、工作流或代码版本
- 实际步骤与关键改动：
- 评估口径：参考标准、评估者或评估方法、范围、指标定义
- 基线与可比性：对照方案或历史结果，以及数据/规则/口径差异
- 结果：观察值、分子/分母、未覆盖部分；无结果时说明原因
- 证据与核验情况：产物、日志、评估表、运行 ID 或用户转述
- 证据粒度与单样本入口：完整明细 / 部分样本 / 仅汇总，样本、尝试和节点定位
- 验收配置与结果：规则/评估器版本、报告引用、未执行检查、缓存或重放来源
- 对假设的判断：支持 / 不支持 / 证据不足，并说明理由
- 限制与异常：失败样本、混杂变化、缺失信息
- 关联问题卡与后续修复验证：
- 后续行动及关联经验：
```

根据实施方式补充真正影响复现的信息：

- **合成数据**：生成条件、样本覆盖、去重或过滤规则、质检方法；生成数量不等于可用数量。
- **质检 / 内容审核**：规则版本、样本选择、参考判定、误判和漏判的定义；申诉或争议样本与明确错误分开。
- **机标**：标签体系、单/多标签口径、参考标注来源、冲突裁决、抽检与返工条件。
- **Agent / 工作流**：节点职责、输入输出、分支与重试、工具依赖；平台无法导出时记录可见配置和运行标识，注明未恢复的细节。
- **代码实施**：版本或文件、关键配置、运行输入输出。没有代码不影响建档。

只有计算口径一致的数据才直接比较。批次、样本量或评估方式不同应披露差异；同一模型自评可以作为结果来源，但不能冒充独立质检。多项配置同时改变时，不直接认定某一项造成提升。

不要将工具调用成功、平台显示“成功”或输出非空作为业务达标证据。成本和耗时仅记录实际获得的数据；缺失时不估造。

需要制定试跑或汇总初步方案评价时，使用 [evaluation.md](evaluation.md)。本表记录实际运行，评价记录引用本表，不复制一份容易失去同步的结果。

## 经验记录

```markdown
### L-001 · 一句话经验

- 结论及状态：待验证 / 限定条件下有支持 / 待复核 / 已被替代
- 入库判定与理由：候选 / 可复用 / 合并 / 仅证据；参照知识生命周期规则
- 支持证据：具体实验或产物链接
- 证据范围与复用类型：方法原则 / 具体实现 / 效果结论；说明哪些条件只是原实验背景
- 观察与动作验证：已核验的现象；推荐动作是未执行 / 有限复验 / 有反例，不用一个 verified 布尔值概括
- 适用条件与已覆盖范围：
- 建议做法及不适用情形：
- 已知反例、失败表现与未解问题：
- 原因解释：区分已验证原因与推测
- 关联 SOP：存在时引用
- 有效性与召回验证：范围/绑定版本、最近验证、复核事件、业务查询及结果引用
- 发现与采用：业务术语映射及依据、候选是否在实际阅读窗口内、是否经适用性审查进入方案；保留原查询失败与补查结果
- 复用前提与证据范围的差异：新需求必须满足什么、只可参考什么、哪些效果必须重验
- 修订记录：什么新证据改变了哪些判断
```

“方法有效”应改成可操作的有边界结论，如“在这类输入和该规则版本下，加入某校验减少了已观察到的某类错误”。证据不足时保留假设，不硬凑经验。

经验门槛、时效和交付回执使用 [knowledge-lifecycle.md](knowledge-lifecycle.md)，不以 SOP 采纳状态、重复提及次数或一次检索命中代替效果证据。

## 增量与冲突

- 同一运行的新附件或统计补进原实验；修正数值时说明旧值、修正值及依据。
- 重跑、换批次或关键条件改变时建立新实验，链接原尝试，不覆盖对照。
- 新结论改变旧经验时，保留历史证据和当前状态，并更新索引及相关 SOP。
- 来源互相矛盾时并列说明冲突和待核验点，不取更乐观或更新的说法作为事实。
- 未执行的下一步留作计划；不要仅为补齐记录擅自重跑平台流程或产生外部费用。
